## ✅ 完整 SQL

```sql
SELECT
  product_id,
  product_name,
  description
FROM products
WHERE REGEXP_LIKE(
        description,
        '(^|[^A-Za-z0-9])SN[0-9]{4}-[0-9]{4}([^0-9]|$)',
        'c'
      )
ORDER BY product_id ASC;
```

---

## ① `REGEXP_LIKE(...)` 是什么？

```sql
REGEXP_LIKE(expr, pattern, match_type)
```

* **MySQL 8+ 正则函数**
* 返回 `TRUE / FALSE`
* 比老的 `REGEXP`：

  * 功能更强
  * 语义更清晰
  * 支持匹配模式参数（如大小写）

---

## ② 第一个参数：`description`

```sql
REGEXP_LIKE(description, ...)
```

意思是：

> “判断 **description 字符串中** 是否存在符合正则规则的子串”

⚠️ 注意：
这里**不是全文匹配**，而是 **“只要有一段匹配即可”**（这正是题目要求的）

---

## ③ 第二个参数：正则表达式（核心）

```regex
(^|[^A-Za-z0-9])SN[0-9]{4}-[0-9]{4}([^0-9]|$)
```

我们拆开来看 👇

---

### 🔹 `( ^ | [^A-Za-z0-9] )`

* **字符串开头**
  或
* **前一个字符不是字母或数字**

📌 作用：

* 防止误匹配：

  * ❌ `ASN4321-8765`
  * ❌ `XSN1234-5678`

---

### 🔹 `SN`

* 必须是 **大写 `SN`**
* `sN` / `Sn` / `sn` 都不行

---

### 🔹 `[0-9]{4}`

* **严格 4 位数字**
* 不多不少

---

### 🔹 `-`

* 必须有连字符

---

### 🔹 `[0-9]{4}`

* 再来 **严格 4 位数字**

---

### 🔹 `( [^0-9] | $ )`

* 后一个字符：

  * 不是数字
    **或**
  * 已经是字符串结尾

📌 作用：

* 排除：

  * ❌ `SN1234-56789`

---

## ④ 第三个参数：`'c'`（**关键**）

```sql
'c'
```

这是 **match_type（匹配模式）**：

| 参数  | 含义                        |
| --- | ------------------------- |
| `c` | **case-sensitive（区分大小写）** |
| `i` | case-insensitive          |
| `m` | multi-line                |
| `n` | `.` 匹配换行                  |

📌 **`'c'` 的作用：**

* 强制 `SN` 必须是 **大写**
* 排除：

  * ❌ `sN4321-8765`
  * ❌ `sn1234-5678`

👉 这就是你之前用 `BINARY` 时踩坑、现在能完美解决的原因。
